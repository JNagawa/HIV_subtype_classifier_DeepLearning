# HIV Subtype Classifier: Execution Instructions

Follow these steps exactly to run the complete data pipeline, from raw sequence acquisition to model deployment.

### 1. Environment Setup
It is highly recommended to run this project in a GPU-accelerated environment (like Google Colab or a local machine with an NVIDIA GPU).

```bash
# Clone the repository
git clone https://github.com/YourUsername/hiv-subtype-classifier.git
cd hiv-subtype-classifier

# Install all required dependencies
pip install -r requirements.txt
```

### 2. Pipeline Execution
The project is divided into 7 sequential Jupyter Notebooks located in the `notebooks/` directory. You must run them in chronological order, as each notebook generates data and model artifacts required by the next.

* **Notebook 01: Data Acquisition**
  Run `01_data_acquisition_and_exploration.ipynb` to parse the LANL accession numbers and download the raw FASTA sequences to `data/raw/`.
  
* **Notebook 02: Preprocessing**
  Run `02_preprocessing.ipynb`. This will clean the sequences, pad/truncate them to a uniform length, and serialize the data into PyTorch-ready tensors saved in `data/processed/`.

* **Notebook 03: Baseline Model**
  Run `03_baseline_model.ipynb` to train a simple Multilayer Perceptron (MLP) on the sequences.

* **Notebook 04: Deep Learning**
  Run `04_deep_learning_models.ipynb` to train the 1D-CNN and the BiLSTM. This notebook is computationally heavy and requires a GPU. It will save the best weights to the `models/` directory.

* **Notebook 05: Evaluation**
  Run `05_model_evaluation_and_comparisons.ipynb`. This notebook automatically loads all models, compares their precision/recall against the test set, and generates Universal Saliency Maps to explain the model's confidence visually.

* **Notebook 06: Transfer Learning (Optional)**
  Run `06_transfer_learning.ipynb` to download and fine-tune DNABERT (a Transformer pre-trained on the human genome). Warning: This requires substantial VRAM.

* **Notebook 07: Deployment**
  Run `07_deployment.ipynb`. This script acts as a mock production environment. It dynamically scans the `data/processed/training_histories.pkl` file, identifies the absolute best-performing architecture, loads its weights natively from `src/models.py`, and stands ready for inference.
